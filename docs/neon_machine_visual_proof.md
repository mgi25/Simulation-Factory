# Neon Marble Machine — visual proof (V1 prototype)

A short art-direction prototype, built to answer one question before any of
the hero course is built:

> If we pause on a random frame, does it obviously look three-dimensional?

Three sections only — a start platform, a mixing bowl, an S-curve bridge,
plus the joins between them — rendered through the real pipeline at real
production resolution. No new
physics engine, no procedural generation, no audio, no curation. The V0.4
race and the fight system are untouched.

The reference is `docs/references/neon_marble_machine_concept.png`, and the
target was its **hierarchy** rather than its details: a pale silver track on
dark graphite structure, a glass-and-metal bowl, a suspended bridge with air
under it, restrained cyan accents, and levels a viewer can see are levels.

---

## How to run

```bash
# everything: replay, camera sweep, sequence, stills, video, country still
python tools/neon_proof.py --seed 7 --all

# or one step at a time
python tools/neon_proof.py --seed 7 --replay
python tools/neon_proof.py --seed 7 --cameras --angles 42,48,52,56
python tools/neon_proof.py --seed 7 --frames --elevation 52
python tools/neon_proof.py --seed 7 --sections --video --countries

# preview the course itself, with no renderer involved
python race_main.py --course neon --racers 16 --seed 7 --headless
```

Godot is found the way the rest of the project finds it: `--godot`, then
`$GODOT_BIN`, then the PATH.

## Part 1 — where V0.4 actually fails

The V0.4 renderer is not badly lit and it is not low detail. It fails at one
specific thing, and it is worth naming precisely because the fix follows from
it.

`race_scene.gd` draws *any* course. It has to: it plays three courses it has
never seen, so it recognises a piece by its `role` and by its angle, and it
can know nothing about what the course **is**. A funnel arrives as a set of
angled bars, so a funnel is drawn as a set of angled bars. Every trick in that
file — beam depth from the piece's slope, struts under flat pieces, a deck
that steps down per section — is an attempt to infer three-dimensionality from
a description that does not contain any.

That is the ceiling. A bowl cannot be drawn as a bowl by something that does
not know a bowl is there.

So this prototype does the opposite thing, and only for this course: the
course **exports** where the bowl is, and the scene is told.

```python
# race/courses/neon.py — builder.finish(...)
bowl_centre_x=540.0, bowl_centre_y=1820.0, bowl_radius=470.0,
bowl_top=1350.0, drain_half=110.0, drain_y=1820.0,
gate_y=740.0, platform_left=95.0, platform_right=985.0,
throat_end=2200.0, bridge_top=2200.0, bridge_end=3800.0,
```

Those numbers ride in `course.metadata`, which the replay exporter already
carries. Nothing in the simulation reads them. `neon_scene.gd` reads all of
them and hard-codes none, so the mapping, the bowl mesh and the camera are all
built from one description and cannot disagree with each other.

## Part 2 — the presentation-height mapping

The physics stays two-dimensional and is never touched. Simulation x becomes
world X and simulation y becomes world Z, one to one, with no warp — so two
racers touching in the simulation are touching on screen, and no pair can be
drawn intersecting that is not intersecting.

The whole third axis is derived by one function, `deck_height(sim_x, sim_y)`:

```
  simulation x, y
        ↓
  which stretch of the machine is this?
        ↓
  start    →  flat, the highest surface
  chute    →  eased descent, H_START → H_RIM
  bowl     →  H_RIM − BOWL_DEPTH × profile(rho)      ← the interesting one
  throat   →  eased descent below the drain
  bridge   →  gentle descent to H_BRIDGE_END
```

with

```
rho          = |(x, y) − bowl_centre| / bowl_radius
profile(rho) = 1                       for rho ≤ 0.26      (the flat floor)
             = 1 − q^1.9,  q = (rho−0.26)/0.74            (the wall)
             = 0                       for rho ≥ 1.00      (the lip)
```

**Why radial.** A marble far from the bowl's centre is high on the wall and a
marble near it is at the floor, which is what a bowl *is*. It also makes free
fall do the right thing for free: falling in the simulation reduces the
distance to the bowl centre, so a racer dropping in from a spout is drawn
sliding down the inner surface rather than through it.

**Why it is safe.** The bowl mesh is generated by evaluating the same
function. A racer sits at `bowl_surface_y(rho) + its radius`, and every vertex
of the mesh under it is `bowl_surface_y` at that vertex's own radius. Contact
is exact by construction rather than by tuning — it cannot sink into the bowl
and it cannot hover over it, whatever the solver does.

**What has to be true for it to hold.** Every point a racer can reach inside
the bowl must be inside the disc the mesh covers. That is a property of the
*course*, so the course is laid out as a disc: the basin walls are placed on a
circle at 0.95 of the radius, and the seam where the spouts hand over is
exactly one radius above the centre, so a racer arriving anywhere along it is
at the rim rather than halfway down. Measured over the whole reference replay,
the furthest any racer gets is **rho = 1.11**; the drawn lip runs to 1.16.
`tests/test_neon_proof.py::test_no_racer_ever_leaves_the_drawn_bowl` asserts
it against a recorded race, because the failure mode is sixteen marbles
hanging in mid-air and nothing else in the pipeline would notice.

### Height hierarchy

| Surface | World Y | Note |
| --- | --- | --- |
| Start platform deck | `0.00` | highest |
| Bowl lip | `−2.60` | chute descends at 23° |
| Bowl floor / drain | `−5.20` | 2.60 deep |
| Throat exit | `−6.20` | |
| Bridge, at its end | `−9.20` | 10.6° along the S-curve |
| Room floor | `−19.00` | ~10 units of air under the bridge |

The first version of this table was half as tall and the machine read as one
continuous pale slope: a 10° ramp is a floor, not a level change. Doubling the
drop is what gave the chute a lit edge, a thickness and a shadow of its own,
and put the bowl visibly *beneath* the platform rather than beside it.

## Part 3 — the bowl, as geometry

Built as a surface of revolution in `_bowl_revolution()`: 128 segments around,
44 rings from the drain to the lip, normals taken by difference from the same
height function so they cannot drift away from the surface.

| Part | What it is | Why |
| --- | --- | --- |
| Inner surface | opaque light silver, `rho 0.23 → 1.00` | the racing surface. Opaque so a marble on it has a contact shadow and the curve has a terminator — the two cues that say "curved solid" |
| Lip / flange | a second surface, `1.00 → 1.16`, one value deeper | a dish and a flange in one tone read as a satellite dish; two tones read as a vessel in a machined rim |
| Underside | the same shape, dropped 0.26, wound over | gives the vessel wall a thickness at the rim |
| Acrylic shell | a larger vessel around it, dropped 0.95, 11% wider, 26% alpha | the glass is *outside* the racing surface, so it costs no readability |
| Machined seams | two thin rings at `rho 0.52` and `0.78` | a bowl with no surface incident renders as one enormous smooth gradient, and a gradient does not read as a manufactured object |
| Drain collar + well | lit ring at `rho 0.23`, dark cylinder 2.6 below | the exit reads as a hole with depth under it, not a gap |
| Cradle | hoop at `rho 0.86`, six radial ribs, six legs to the floor | the metallic support the brief asks for; the vessel is *held*, not placed |

The lip is bevelled downward by 0.05 across its width — mesh only. The chute's
spouts end *on* the lip and two coplanar decks fight for the depth buffer in a
band exactly where the field pours in. A racer clamped onto the lip is then
that much above it: five simulation pixels, a twentieth of a marble.

### The exit

One drain, central, 220 course pixels clear — three and a half racer
diameters, comfortably past the width two marbles can arch across. Below it
the throat is a real channel, not a gap: a swept solid that descends away from
the drain and is visible through the opening, with a dark sleeve behind it.

The throat is the one deck built with a *negative* margin. Everything else
reaches past its walls by a rail's width so the rails have something to stand
on; the throat has to stay inside the hole cut in the bowl, or it meets the
bowl floor at its own height and fights it all the way round the opening.

## Part 4 — decks, derived from the walls

Nothing describes the shape of the chute, the throat, the bridge or the catch.
One builder samples each section every 26 course pixels, asks what is clear
between its walls at that height, and sweeps a solid through the answer.

Five details in there are decisions rather than mechanics:

**Only gaps walled on both sides are channels.** The first version paved
anything clear, including the open air beside the machine: the chute came out
ten units wide with the spouts drawn as scratches on it.

**A wall is measured where the plane actually cuts it.** The first version
took each rotated box's axis-aligned extent, which is the same at every height
— so a wall that *leans* claimed the same slice of the x axis all the way down
itself. The finish apron is one long ramp per side flaring from 300 pixels
wide to 810, and it came out as a deck of one constant width: the rails stood
up in the middle of the basin and six of the sixteen marbles ended the race
standing in the void beside them. Clipping the box's outline against the plane
is exact, and it is what makes a flaring or curving channel get the deck it
actually has.

**Edges are smoothed over ±3 samples.** Consecutive wall boxes overlap at
every joint and the wider claim wins there, so a curved wall's inner face has
a shallow corner at each joint. The window is a hair over one box; the curve
is two orders of magnitude longer and is untouched.

**Where the number of channels changes, the sweeps abut on one plane.** The
chute's single apron becomes two spouts the moment the wedge's dome appears,
and the first version closed the old run at one sample and began the new ones
at the next — a full sample step with nothing swept between, and because every
run is capped at both ends, that is an open slot right across the deck rather
than a seam. The whole field of sixteen was drawn crossing it. They now meet
at the midpoint of the step: the closing run's end cap and the opening run's
start cap are coplanar with opposite normals, so whichever faces the lens is
the only one drawn.

**Three materials per deck, never one.** Pale top, dark side, darker
underside. That single contrast is the whole reason a beam reads as a beam,
and a recessed centre panel plus a deeper spine keep a wide pale surface from
reading as a sheet of paper. They run *along* the direction of travel: a line
drawn across a deck reads as a rung, which is the diagram look this prototype
exists to get away from.

Under the chute and the bridge, posts every 2.6 units drop to the room floor
with a cap, a foot and one horizontal brace between neighbours. A deck with
air and a shadow beneath it is unmistakably an object; without something
crossing that space, ten units of darkness is only darkness.

## Part 5 — the release

The mapping decides what the release looks like, and it is worth stating.
Simulation y runs down the course and becomes world Z, so a marble falling in
the simulation travels **forward and down** on screen. The gate in the
simulation is the platform floor, removed on one tick; on screen that is
sixteen marbles rolling forward over the lip together. So the drawn gate is a
barrier across the front of the deck, not a trapdoor underneath — same event,
honest picture of it.

Eight blades on a graphite frame with polished faces and a cyan bar along the
top, dropping into a housing let into the lip. They are animated to *finish*
moving on the tick the replay records the gate open, not to start there, so no
marble is ever drawn passing through a blade that has not got out of the way.

## Part 6 — the camera

`tools/neon_proof.py --cameras` renders the same four moments of the same
replay through the same scene at each elevation; only the lens differs. Stills
are under `docs/validation/neon_v1/camera/e42/`, `e48/`, `e52/`, `e56/`.

| | Bowl | Bridge | Verdict |
| --- | --- | --- | --- |
| **42°** | clipped at the frame edges, and most foreshortened | small and distant, and the posts are hidden behind the deck they hold up | rejected: the one thing the bridge exists to prove does not read |
| **48°** | fits, good depth | visible, posts only just legible | rejected: the bridge is still weak |
| **52°** | fits with a clear far wall, whole interior readable | stands above its own shadow with the posts in view | **selected** |
| **56°** | very similar to 52, slightly rounder | slightly more of it visible | close second, rejected on height (below) |

**Selected: 52°**, FOV 40, portrait 1080×1920.

42 and 48 were rejected on the bridge. The choice between 52 and 56 was close
and went to 52 for one measurable reason: a height difference projects onto the
screen's vertical axis in proportion to `cos(elevation)`, so at 52° the seven
units between the platform deck and the bridge separate about 10% more than
they do at 56°, and the brief asks specifically for the height hierarchy to be
visible. 56 shows marginally more of the course; that is not what is being
proved here.

The distance is derived, not dialled: the course is fitted across the point
the lens is aimed at, `D·tan(h) = half the course + 0.7`. The race scene fits
at the *near* edge of the frustum instead, which is right for a course that is
full width end to end and wrong here — it puts the lens forty units out to
protect ground the machine does not stand on, and the machine then takes a
third of the frame with the rest given to the room.

### The move

One flowing shot, no cuts. Every term is a smoothstep of the aim's course
height, so the framing is a pure function of the playhead: seeking anywhere
gives the same frame, and two renders agree exactly.

| Phase | Distance | Elevation | Aim |
| --- | --- | --- | --- |
| Platform | ×1.15 | 52° | rides the deck |
| Into the bowl | ×0.97 | 49° | drops 0.35 to look in |
| Along the bridge | ×1.00 | 50° | lead extended by 520px |

Under all of it, a slow orbit of eight degrees applied to the camera position
and not to the aim — so the machine stays centred while the near columns and
the far columns sweep across the frame at visibly different rates. That
difference is the parallax cue, and it is the cheapest one there is.

## Part 7 — materials

`godot/scripts/neon_materials.gd`. Three rules: the track is light and the
structure is dark; nothing is emissive unless it is a light; the picture has
to survive with bloom off.

| Role | Colour | Finish |
| --- | --- | --- |
| Track surface | `#858A8F` light silver, not white | metallic 0.28, roughness 0.30 |
| Deck side / underside | `#2B2F34` / `#1C1E23` | the part that says a beam has thickness |
| Structure | `#191B20` graphite, `#262A30` where it faces the key | metallic 0.55 |
| Rails | `#8F9AA6` | metallic 0.88, roughness 0.18 — near-mirror |
| Bowl surface | track silver + clearcoat | roughness 0.34 |
| Bowl shell / cradle | `#414950` brushed | metallic 0.82 |
| Acrylic | `#9EC7DE` at 26% alpha | roughness 0.04 |
| Cyan accent | `#54D0FF` | edges, rails, drain collar, start |
| Violet accent | `#8F6EFA` | the light across the bowl's rim, and every third strip on the far wall |
| Racers | the sixteen V0.4 hues | metallic 0.12, roughness 0.12, clearcoat 0.85, rim 0.55 |

Pure white was tried first and clips under ACES, taking the surface's shading
with it — which is how a deck stops looking like a solid.

The racers have **no emission at all**, which is the one real departure from
the V0.4 racer material. An emissive sphere is bright everywhere, so it has no
terminator and no shading, and at Shorts scale it flattens to a coloured disc.
A clearcoat gives a small hard white highlight that does not take the hue with
it, and a rim light keeps sixteen of them separable in a pile-up — neither
costs any shading.

### Lighting

A key at −46°/36°, **across** the machine rather than down it, at energy 1.65
with four-split shadows out to 96 units. That direction is the whole reason
the machine has shape: a light straight overhead puts every shadow underneath
the thing casting it, so the bridge would have no visible underside, the posts
no length and the bowl no terminator. A cool fill at 0.80 and a kicker almost
along the lens axis at 0.80 for the edge on every marble. Two low omnis inside
the bowl, cyan at the drain and violet across the rim.

Glow threshold 1.05, intensity 0.42. Two things on the machine cross it: the
start treatment and the drain collar. Everything else is a lit surface.

The brief asks for a picture that still looks good with bloom disabled, so
that was rendered rather than asserted: the same frame with
`glow_enabled = false` is all but indistinguishable from the shipped one — the
START panel and the drain collar lose a small halo and nothing else changes.
Every value, edge and shadow in the frame comes from albedo, roughness and the
key light, which is what "no overwhelming bloom" has to mean if it is to mean
anything.

## Part 8 — the environment

A dark chamber, not a slab behind the track. The floor is nineteen units down,
the columns stand in two ranks at eleven and fifteen and a half units out —
the near rank clearing the bowl's lip, which reaches 5.45 — and everything
between them is air that the posts and the bowl's legs cross. Depth fog from 34 to 108 units, which is where this machine
actually sits — the race scene's fog begins at 20 and would haze over the
subject at this framing.

Cross-beams reach in from each wall and stop well short of the middle. They
ran the full width in the first version and it was the race scene's gantry
lesson again in a new place: a horizontal bar across a portrait frame reads as
letterboxing, and two of them read as a fault in the render.

The sky is the most important object in the scene and is never drawn. Nearly
every surface here is partly metallic, so what it shows is whatever the
environment gives it to reflect; with no reflection source a light silver deck
renders as flat grey paint and a polished rail as a black stripe.

## Part 9 — the country experiment

`--neon-countries` swaps the first five racers' materials for stylised
flag-inspired ones, generated in code, and nothing else about the scene
changes. Both stills are the same frame of the same replay, so the only
difference between them is the racer material.

Rectangular flag PNGs stretched over spheres are what the brief rules out, and
they deserve to be: the equirectangular map compresses everything towards the
poles, so a wrapped flag arrives as a smear with a pinched top and bottom.
What survives that projection is bands of *latitude* and a motif on the
equator — which is, conveniently, what a designed marble looks like. So each
is the flag reduced to those two ingredients, with longitude corrected by
`cos(latitude)` so a Japanese marble's red circle is actually round.

**Verdict, offered rather than decided:** the flags read at rest and lose most
of their identity in motion, because a rolling sphere spends half its time
showing the back of the pattern. Germany and Japan survive it (one motif, high
contrast); India and the USA do not (fine bands and small emblems go to mush).
If country identity is wanted, the flag should be a *badge* on an otherwise
plain glossy marble — which is also what the concept sheet's own note
suggests. Not carried into the racer system, as instructed.

## Part 10 — determinism

The prototype scene inherits the pipeline's rule that a frame is a pure
function of the playhead, and it was checked rather than assumed. Frames 145,
301 and 439 were rendered by two separate Godot processes, from the same
replay, before and after an unrelated refactor of the camera's phase
boundaries, and the rendered PNGs are **byte for byte identical**:

```
start_platform   609eea2c99bab937  609eea2c99bab937
inside_bowl      e0bbf95b417e127d  e0bbf95b417e127d
s_curve_bridge   60ffe6dfaf99babe  60ffe6dfaf99babe
```

Nothing in `neon_scene.gd` accumulates across draws. The camera's framing is
computed from the frame in front of it, the shutter's position from the tick
the replay records the gate open, and the racers from two frames and a blend.
The country textures are generated from an index with no randomness in them.

The V0.4 path was checked the same way, because the one file this prototype
touches is the one that dispatches it. Three moments of
`output/race_v04/machine_20588_r16.json` were rendered through the production
race scene with `replay_viewer.gd` at its committed state and again with the
`--race-style` branch added, and all three came back byte for byte identical:

```
still_000210     5cb81a0a60504729  5cb81a0a60504729
still_000840     54f16ced5ec59ae8  54f16ced5ec59ae8
still_001440     9f241a80fd9d3ead  9f241a80fd9d3ead
```

## Part 11 — the course audit, and where a racer can actually get

`python -m tools.course_audit --all` is the project's own geometry gate, and
the neon course passes it at the same bar as the other three:

```
=== COURSE AUDIT: prototype ===   errors 0   warnings 3
=== COURSE AUDIT: split ===       errors 0   warnings 17
=== COURSE AUDIT: machine ===     errors 0   warnings 11
=== COURSE AUDIT: neon ===        errors 0   warnings 21
```

It did not, first time round: six **pinch traps** — gaps too narrow for a
racer to pass and, on the audit's reading, somewhere one could be driven into.
All six were pockets nothing can reach, and all six were worth closing rather
than explaining, because a pocket that only geometry keeps a racer out of is
still a pocket:

| Was | Fix |
| --- | --- |
| 43px outside each platform rail | rails widened to 54px so they sit flush against the boundary |
| 48px outside each chute wall, once it began to lean in | chute walls start at the boundary rather than at the platform edge |
| 52px inside the wedge, between two walls sharing an apex | the wedge is one solid slab under a dome as wide as itself |
| 18px where a throat wall met a bridge wall | the throat flares out to exactly where the bridge's walls begin |
| 47px behind the S-curve at the crest of its swing | amplitude 290 → 268, which keeps that strip a passage rather than a wedge |

The remaining twenty-one are **arch risks** — gaps a racer fits through that
two could bridge across — and **balance points**, the same two categories the
machine course carries eleven of. The tightest, a 72px strip outside the
bowl's basin wall, was measured rather than argued about: over **30 seeds ×
16 racers**, the furthest any racer ever gets inside the bowl-and-throat band
is x = 239 on the left and x = 836 on the right, against a strip that starts
at x = 107. Nothing comes within 130 pixels of it.

The same sweep is why `seed 7` is the one the proof ships on: 29 of those 30
seeds finish all sixteen racers with no recoveries and no retirements, and
seed 7 is one of them. A recovery teleports a racer, and a teleport inside a
seven-second clip is the one thing a viewer would certainly notice.

RTX 3050 Laptop, Vulkan Forward+, 1080×1920, MSAA 2×.

| | |

| Whole 631-frame sequence | a little over one second of GPU time |

The prototype is nowhere near a budget. The bowl is the most expensive object
in the scene and its four surfaces come to about 24k triangles, built once.

## Part 13 — what this does not do

Deliberately absent, per the brief's scope: the collector machine, the split
choice, the final compression, the finish arena, procedural generation, race
audio, curation, and the country balls as a system.

Real limitations, which is a different list:

* **The chute apron is still the largest pale surface in frame.** Narrowing
  the funnel and giving it a spine helped; it still takes the bottom third
  during the bowl sequence, and it hides the bowl's cradle from a 52° lens.
  The hero course should route the field into the bowl on a *track* rather
  than an apron.
* **Racers are hidden for about half a second in the throat**, between the
  drain and where the bridge emerges from under the bowl's far rim. It reads
  as the drain swallowing them, which is defensible, but it is an accident of
  the geometry rather than a decision.
* **The bowl's acrylic shell barely reads at this elevation.** It is under the
  vessel, and at 52° there is very little of it in view. It would earn its
  place at a lower angle or in a wider establishing shot.
* **No trails, no impact effects, no HUD.** Switched off on purpose so the
  architecture is what gets judged, but the finished thing will need them and
  they will change the exposure balance.
* **One seed, one course.** This is an art-direction proof, not a balance
  pass. The race has not been designed or measured for fairness, pack size or
  predictability the way the machine course was; the only thing measured about
  it is that it does not break (Part 11).
* **The deck builder assumes a course is a channel between two walls.** It
  copes with the chute splitting into two spouts because the count of gaps is
  tracked, but a genuine fork with two long parallel routes would need the
  matching to be smarter than "same count, same order".
* **The deck builder has no test, and it earned one.** Two of its three
  defects — a wall measured by its axis-aligned extent, so a flaring channel
  got a constant-width deck, and a full sample step of nothing swept where the
  channel count changes — were found by porting `_piece_span`,
  `_clear_spans` and `_deck_ribbons` to Python and running them against the
  reference replay, then projecting the racer positions onto the rendered
  frames. Both put marbles over nothing, which is the one thing the whole
  mapping exists to make impossible. Nothing in the pytest suite can reach
  GDScript; if the hero course reuses this builder, that port is the thing to
  keep, not the memory of the bugs.

## Tests

`tests/test_neon_proof.py`, 25 tests, and the whole suite is 1089 passing.

The unusual half are the ones that assert the *presentation contract* rather
than the course: that every point a racer reaches inside the bowl is inside
the drawn disc, measured on a recorded race; that the bowl seam is exactly one
radius above the centre; that the scene ships on the elevation the tool
selects, read out of the GDScript, because a comparison shot at one angle and
delivered at another would be a silent lie nothing else would catch.
