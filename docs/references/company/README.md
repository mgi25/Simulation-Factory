Source documents the company reasons against, kept in the repository so a later
session can read them without being handed a file.

## Simulation Factory AI Company Master Development Plan

- `Simulation_Factory_AI_Company_Master_Development_Plan.docx` — the original,
  byte-for-byte as supplied by the CEO. Planning Baseline v1.0.
- `simulation_factory_master_development_plan.md` — the same document extracted
  to Markdown so it is greppable, diffable, and readable without Word. Headings,
  lists and tables are preserved; the extraction adds nothing and drops only
  styling.

**This is the strategic design baseline, not the technical source of truth.**
Where it conflicts with architecture that has since been built and validated,
the validated architecture wins and the discrepancy is written down rather than
silently overwritten. The six conflicts found so far are reconciled in
[`../../company_os_executive_delegation.md`](../../company_os_executive_delegation.md)
§1 — the CFO and Engineering Manager seats that no registry row fills, the
executive reporting lines, the CTO/`chief_architect` mapping, and the autonomy
ladder and CEO-reserved list that are already canonical in
`company/permissions.yaml` and are read rather than restated.

If the plan is revised, replace both files together and re-check that section.
